# 查找并拉取 HQ Git

从 HQ 项目映射中定位仓库。始终先搜索和展示候选项，再让用户选择；未经明确确认，不得执行任何会访问远程仓库的 `git clone` 或 `git pull`。

## 固定资源

- 映射文件：`references/hq_team_project_git_mapping.md`
- 搜索脚本：`scripts/search_hq_git.py`
- 拉取脚本：`scripts/sync_hq_git.py`

默认使用 Skill 内置的映射快照，脚本会基于自身位置解析该相对资源路径，不依赖当前工作目录。只有在用户明确指定其他映射文件时，才使用 `--mapping` 覆盖默认值。若内置映射不存在，先告知用户，不要回退到机器上的外部绝对路径。

## 工作流

### 1. 搜索候选仓库

从用户表述中提取名称，不要求它是完整项目名。运行：

```bash
python3 scripts/search_hq_git.py "<名称>" --limit 15
```

搜索覆盖项目名、每个 VOPS 应用名、相对路径、仓库名和 Git 地址。脚本会处理大小写、连字符/下划线/空格差异和近似拼写，并按匹配度降序输出。

如果没有结果，尝试一次更短且有辨识度的关键词；仍无结果则说明未找到，并请用户补充名称或映射来源。不要自行猜测 Git 地址。

### 2. 展示并让用户选择

以脚本顺序展示候选结果，至少包含：编号、匹配分、项目名、VOPS 应用名、相对路径和 Git 地址。候选较多时先展示前 10–15 条，不要把低相关项伪装成确定结果。

随后询问：

1. 拉取全部候选、指定编号，还是都不拉取；
2. 目标目录；用户未指定时建议当前工作目录；
3. 多仓库布局需要确认时，选择 `flat`（各项目直接位于目标目录）或 `relative`（保留 hq.team 相对路径）。默认 `flat`。

将同一个 Git 仓库对应的多个 VOPS 应用视为一个候选仓库，不重复拉取。用户可以用编号、项目名或“全部”选择。

### 3. 等待明确确认

搜索和展示不会构成拉取授权。必须在用户明确选择项目且确认目标目录后，才能执行下一步。不要因“看起来就是这个”“继续看看”等含糊回复开始拉取。

执行前复述最终项目清单、目标目录和布局。如果用户的当前消息已经明确给出这些信息并明确要求执行，可以直接执行；否则先询问。

### 4. 克隆或更新选中项目

使用项目名调用脚本，不要把模糊查询直接传给拉取脚本：

```bash
python3 scripts/sync_hq_git.py \
  --destination "<目标目录>" \
  --layout flat \
  --project "<项目名1>" \
  --project "<项目名2>"
```

脚本行为：

- 目标不存在：执行 `git clone`；
- 目标是对应 Git 仓库：执行 `git pull --ff-only`；
- 目标存在但不是 Git 仓库，或 `origin` 与映射地址不一致：拒绝覆盖并报错；
- 某项目失败时继续处理其余项目，并最终返回失败状态。

若用户只想预览命令，加 `--dry-run`。不要通过手写命令绕过脚本的目标路径和远程地址检查。

### 5. 汇报结果

逐项报告 `cloned`、`updated`、`would-clone`、`would-update` 或 `failed`，并给出本地路径。若认证、网络、工作区改动或非快进更新导致失败，保留现场，说明错误；不要自动改凭据、强制覆盖、重置或清理仓库。
