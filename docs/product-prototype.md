# FlowWeave MVP 产品原型

浏览器原型入口：[打开 FlowWeave MVP 产品原型](./prototype/index.html)

## 产品范围

FlowWeave MVP 聚焦 Agent 节点资产、模型配置、流程编排和流程运行四个核心模块。原型顶部提供“当前实现 / 产物驱动提案”切换：当前实现按照当前 React 前端的导航顺序、页头、列表/画布/运行工作台和 Agent 对话布局建立基线，产物驱动提案只表达待确认的增量产品形态，不代表功能已经开发。原型中的业务记录是用于串联交互的示例数据，不会复制本地数据库中的实时记录。

## 已确认的核心规则

- 节点资产按目录分类管理；节点定义模型、可选默认 Skill、提示词、Skill/MCP/Hooks 能力以及输入输出定义。
- MCP 与 Hooks 能力配置支持 JSON 和 YAML；Skill 使用 ZIP 导入并解析 `SKILL.md`，兼容根目录单 Skill 和按子目录批量导入。
- 流程通过可拖拽画布编排，节点可配置多条开始门禁和结束门禁；脚本门禁同时支持 JavaScript 与 Python。
- 每次运行保存独立流程快照，不受节点编辑态影响；用户可明确选择将最新节点配置同步到运行，历史执行和产物保持不变。
- 流程运行按“流程编排 → 运行实例”两级结构管理。
- 节点是否可运行取决于输入产物是否满足输入定义与开始门禁，不依赖上游节点状态。
- 节点输入引用类型兼容的产物版本；产物来源只用于血缘和审计，不参与节点就绪判断。流程可基于已有产物从任意节点重新开始。
- 节点修订默认在当前节点创建新的 Attempt。所有输出按版本保存，下游节点明确引用具体产物版本，历史版本不被覆盖。

## 本轮增量提案

- 一次 Flow Run 是任务上下文与产物池，创建时不再强制填写默认入口节点的输入。
- 同一个 Flow Run 中，一个流程节点只有一个稳定的节点工作项；重新执行通过新增 Attempt 表达。
- 流程连线升级为显式输入来源规则，编排态定义推荐来源，运行态由人工确认具体 ArtifactVersion。
- 人工、历史节点、外部系统和 Agent 生成的产物统一进入任务产物池；节点只关心类型、Schema 和审核状态。
- 下游输入满足后只进入 READY，不自动运行；人确认输入绑定后再启动 Attempt。
- Agent 输出先成为候选产物，必需输出齐全并通过审核后才写入正式产物池；缺少必需输出时禁止验收。

## 基线与提案的使用方式

1. 先在“当前实现”模式核对已经上线的页面结构和概念。
2. 切换到“产物驱动提案”查看相同页面上的增量变化。
3. 本轮只确认产品形态；数据库、API、状态机和运行逻辑暂不修改。
