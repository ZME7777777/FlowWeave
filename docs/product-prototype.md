# FlowWeave MVP 产品原型

浏览器原型入口：[打开 FlowWeave MVP 产品原型](./prototype/index.html)

## 产品范围

FlowWeave MVP 聚焦 Agent 节点资产、模型配置、流程编排和流程运行四个核心模块。本版原型直接呈现预设的目标产品形态，不再提供当前实现与提案的对比切换。原型中的业务记录用于串联交互，不会复制本地数据库中的实时记录。

## 已确认的核心规则

- 节点资产按目录分类管理；节点定义模型、可选启动提示词模板、Skill/MCP/Hooks 能力以及带 Schema 的输入输出契约。
- 节点不保存默认 Skill。每次启动 Attempt 时，用户选择调用某个 Skill、自动发送启动提示词，或只创建会话后手动开始。
- MCP 与 Hooks 能力配置支持 JSON 和 YAML；Skill 使用 ZIP 导入并解析 `SKILL.md`，兼容根目录单 Skill 和按子目录批量导入。
- 流程通过可拖拽画布编排，并明确区分两类连线：节点级“流程走向线”只表达节点之间的流转方向；端口级“产物流转线”定义“上游输出端口 → 下游输入端口”的自动绑定关系。
- 两类连线使用互斥视图：激活“流程走向”时节点线高亮、端口线灰化且不可编辑；激活“产物流转”时端口线高亮、节点线灰化，并允许从输出端口连接到类型兼容的输入端口。
- 节点实例的输入输出端口直接继承节点资产定义，流程不重复定义契约，只保存节点实例、节点走向和端口连接关系。没有端口连接的输入在运行时由人工补充。
- 自动流转只绑定上游新验收的正式产物版本，不自动执行下游节点；运行负责人仍可替换为其他兼容版本。
- 每个节点固定包含不可删除、不可跳过的系统输入门禁，由平台确定性校验必填完整性、产物类型、Schema 和验收状态，不依赖大模型判断。
- 系统输入门禁通过后，再执行可选的业务开始门禁；全部通过后节点进入 READY，仍由人工启动。
- 每次运行保存独立流程快照，不受节点编辑态影响；用户可明确选择将最新节点配置同步到运行，历史执行和产物保持不变。
- 流程运行按“流程编排 → 运行实例”两级结构管理。
- 节点是否可运行取决于输入产物是否满足输入定义与开始门禁，不依赖上游节点状态。
- 节点输入引用类型兼容的产物版本；产物来源只用于血缘和审计，不参与节点就绪判断。流程可基于已有产物从任意节点重新开始。
- 节点修订默认在当前节点创建新的 Attempt。所有输出按版本保存，下游节点明确引用具体产物版本，历史版本不被覆盖。

## 预设运行模型

- 一次 Flow Run 是任务上下文与产物池，创建时不再强制填写默认入口节点的输入。
- 同一个 Flow Run 中，一个流程节点只有一个稳定的节点工作项；重新执行通过新增 Attempt 表达。
- 端口连线保存可选的自动流转规则；规则命中时自动绑定本次验收产生的 ArtifactVersion，未配置时在运行态人工补充。节点走向线不传递产物，也不替代端口映射。
- 人工、历史节点、外部系统和 Agent 生成的产物统一进入任务产物池；节点只关心类型、Schema 和审核状态。
- 下游输入绑定后立即执行系统输入门禁；通过后只进入 READY，不自动运行。
- Agent 输出先成为候选产物，必需输出齐全并通过审核后才写入正式产物池；缺少必需输出时禁止验收。

## 原型重点路径

1. 在流程编排页切换“流程走向 / 产物流转”视图；在产物流转视图点击输出端口，再点击兼容输入端口建立自动绑定，或删除连接改为运行时人工补充。
2. 在流程运行页查看流程态势，识别已验收、当前 READY 和等待输入的节点。
3. 调整节点输入后查看系统输入门禁的即时校验结果。
4. 系统门禁通过后启动节点，并为当前 Attempt 选择 Skill、启动提示词或纯会话模式。
5. 本轮只确认产品形态；数据库、API、状态机和运行逻辑暂不修改。
